# 文書管理

## 基本方針

- 必要以上に細分化せず、文書のまとまりを優先する。
- 同じ情報を複数の場所で管理しない。
- 最初から完璧な分類を求めず、必要になった段階で整理する。
- 一時資料と正式な文書を明確に区別する。
- 正式な文書の構成や記述項目は、原則としてテンプレートで統一する。

## ファイル・ディレクトリの命名

- ファイル名とディレクトリ名は、原則として英語の小文字 kebab-case を使用する。
- READMEやAIツールが認識する規約ファイルなど、慣習上の固定名はその名前を維持する。
- 文書の表示名や説明は、日本語で記述してよい。
- ファイル名だけで意味を表現しきろうとせず、Front Matterの `title` と `description` を利用する。
- ファイル名に空白は使用しない。

## YAML Front Matter

管理対象となる通常の文書には、Markdown本文の先頭にYAML Front Matterを記述する。

```yaml
---
title: 文書のタイトル
description: 文書の目的や内容を簡潔に説明する
category: rules
tags:
  - example
---
```

### フィールド

| フィールド | 必須 | 形式 | 用途 |
|---|---|---|---|
| `title` | 必須 | 文字列 | 日本語の文書タイトル |
| `description` | 必須 | 文字列 | 文書の目的・内容の説明 |
| `category` | 必須 | 文字列 | 文書の主分類。1つだけ指定する |
| `tags` | 任意 | 文字列の配列 | 複数指定できる補助的な分類 |

- `category` は文書の主な所属・性質を示す。複数指定しない。
- `tags` は複数指定でき、異なる分類を横断して文書を見つけるために使う。
- categoryやtagの語彙は、必要が生じたときに既存の値を確認して追加する。最初から網羅的な一覧を作らない。
- `updated` は設けない。更新履歴はGitのコミット履歴で確認する。
- JSONによるメタ情報の別管理は行わない。現時点ではMarkdownを文書の正本とする。

READMEなどの目次・案内ファイル、および `AGENTS.md` や `CLAUDE.md` などのツール規約ファイルは、原則としてFront Matterの対象外とする。

## テンプレート

正式な文書を作成するときは、原則として [テンプレート](../templates/README.md) にある該当テンプレートを使用する。文書ごとに独自の見出し構成や記載形式を作り、同じ種類の文書がばらばらになることを避ける。

### テンプレートの選択・追加

- 文書を作成する前に、既存テンプレートを確認する。
- テンプレートは分野名だけで分けず、記録する目的や用途、必要な情報・構成を基準に分ける。
- 記録する目的や基本構成が異なる場合は、別テンプレートを検討する。
- 一部の項目や利用場面が異なるだけで、基本構成が同じ場合は、同じテンプレートを使用する。
- 既存テンプレートで対応できる場合は、新しいテンプレートを作成しない。
- 同じ形式の文書を繰り返し作成する場合は、テンプレートを用意する。2件程度であっても、今後の継続利用が見込まれ、形式が安定しているなら作成を検討する。
- 件数だけで機械的に判断せず、今後の利用見込みと、共通の構成を定義する価値で判断する。
- 既存テンプレートで対応できず、今後も同じ形式を使う見込みがある場合は、独自形式の文書を作る前にテンプレートの追加・変更を検討する。

### テンプレートの使用

- テンプレートで定義された見出しや基本構成に従う。
- 内容に該当しない項目は省略してよい。項目を埋めるために不要な情報を作らない。
- 情報が未確定の場合は、推測で補完せず、必要に応じて未確認であることを示す。
- 一度限りの特殊な文書など、既存テンプレートが適さない場合は例外を認める。ただし、独自形式を安易に増やさず、最も近いテンプレートの利用を優先する。

テンプレートの追加・変更方法や管理上の詳細は、[テンプレートの案内](../templates/README.md) に従う。

## 配置

- 文書は内容に応じた既存ディレクトリへ配置する。
- 新しいディレクトリは、複数の文書をまとめる必要が生じてから作成する。
- どこに置くべきか判断できない一時的な資料は `tmp/` に置く。
- `tmp/` の内容を正式な文書から直接参照しない。

## 更新・削除

- 既存文書を更新するときは、現在の内容と参照元を確認する。
- 情報が古くなった場合は、必要に応じて更新・移動・削除する。
- 履歴を残す必要がある場合はGitの履歴を利用し、同じ内容を別の変更履歴ファイルに重複して保存しない。
- 文書を削除するときは、他の文書からのリンクや参照も確認する。
